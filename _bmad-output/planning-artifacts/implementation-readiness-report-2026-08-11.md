## PRD 분석

### 기능 요구사항

**FR-001 — Simple Session Start**  
사용자는 비어 있지 않은 고객 이름과 4자리 전화번호 뒷자리를 유일한 필수 시작 입력으로 제공해 활성 세션의 고객용 부스 별칭을 만들고 부스 세션을 시작할 수 있어야 한다.

**FR-002 — Approved Published Preset Catalog Selection**  
사용자는 촬영 전에 1~6개의 승인·게시된 프리셋으로 구성된 제한된 카탈로그에서 하나를 선택할 수 있어야 하며, 직접 편집 도구나 내부 제작 용어에 노출되어서는 안 된다.

**FR-003 — Readiness Guidance and Valid-State Capture**  
사용자는 부스가 준비 중, 촬영 가능, 프리뷰 대기, 내보내기 대기 또는 전화 문의 필요 상태인지 이해할 수 있어야 하며 승인된 유효 상태에서만 촬영할 수 있어야 한다.

**FR-004 — Current-Session Capture Persistence and Truthful Preview Confidence**  
사용자는 활성 세션에 사진을 촬영하고 원본이 안전하게 저장된 후에만 성공 피드백을 받아야 하며, 부스용 프리뷰가 대기에서 준비 완료로 진행되는 동안 현재 세션에 관한 사실 그대로의 안내를 받아야 한다.

**FR-005 — Current-Session Review, Deletion, and In-Session Preset Change**  
사용자는 현재 세션의 사진만 검토하고 `Current-Session Deletion Policy`에 따라 삭제하며, 이미 촬영된 자산을 다시 쓰지 않은 채 이후 촬영에 적용할 활성 프리셋을 변경할 수 있어야 한다.

**FR-006 — Coupon-Adjusted Timing, Warning Alerts, and Exact-End Behavior**  
사용자는 `Session Timing Policy`를 따르는 조정된 세션 종료 시각, 종료 5분 전 음성 경고, 정확한 종료 시점 알림 및 상태별 후속 안내를 신뢰할 수 있어야 한다.

**FR-007 — Export Waiting, Final Readiness, and Handoff Guidance**  
사용자는 촬영 종료 후 `Export Waiting`, `Completed`, `Phone Required` 중 명시적 상태를 거쳐야 하며, 실제 부스 작업이 끝난 뒤에만 `Local Deliverable Ready` 또는 `Handoff Ready`로 완료 안내를 받아야 한다.

**FR-008 — Authorized Preset Authoring, Approval, and Publication**  
권한 있는 프리셋 관리자는 고객에게 제작 도구를 노출하지 않고 초안 작성, 부스 호환성 검증, 불변 게시 버전 승인·게시 및 이전 승인 버전으로의 롤백을 수행할 수 있어야 한다.

**FR-009 — Operational Safety and Recovery**  
운영자는 `Operator Recovery Policy` 범위 안에서 촬영과 렌더 경계의 차단 상태를 식별하고, 제한된 진단·복구 작업과 수명주기 가시성을 사용하며, 고객이 안전하지 않은 복구 절차를 수행하지 않도록 보호할 수 있어야 한다.

**FR-010 — Pre-Opened Full-View Progressive Preset Display**  
사용자는 촬영 전에 준비된 전용 읽기 전용 뷰어에서 현재 촬영과 선택 프리셋에 일치하는 물리적 디스플레이 맞춤 이미지를 먼저 보고, 빈 화면·오래된 프레임·스케일 변화·품질 저하 없이 RAW 정제 이미지로 전환된 결과를 볼 수 있어야 한다.

**총 기능 요구사항: 10개**

### 비기능 요구사항

**NFR-001 — Customer Guidance Density and Simplicity**  
기본 고객 상태 화면 100%는 동적 세션 값을 제외하고 기본 안내 한 문장, 보조 문장 한 개, 기본 동작 라벨 한 개 이하의 문구 예산을 지켜야 하며, 고객 화면에 내부 진단·제작·렌더 엔진 용어가 0개여야 한다.

**NFR-002 — Cross-Branch Preset and Timing Consistency**  
승인된 로컬 연락처 설정을 제외하고 활성 지점 100%가 동일한 승인 프리셋 카탈로그·버전, 고객용 시간 규칙 및 핵심 부스 여정 상태를 사용해야 한다.

**NFR-003 — Booth Responsiveness and Qualifying Viewer Readiness**  
기본 고객 동작은 1초 이내에 응답해야 한다. 승인된 Windows 하드웨어의 사전 오픈 뷰어에서는 신뢰 가능한 촬영 입력부터 실제 모니터 표시까지 첫 적격 프리셋 적용 이미지를 warm p50 3초 이하, p95 4초 이하, 최대 5초 이하로 제시해야 한다. 100회 warm 릴리스 실행은 실패·타임아웃을 제외하지 않고 성공률 99% 이상과 잘못된 프레임 0건을 만족해야 한다.

**NFR-004 — Session Isolation and Privacy**  
원본 촬영, 프리뷰, 최종 출력, 검토, 삭제 및 완료 흐름 전체에서 세션 간 자산 노출이 0건이어야 하며 활성·재개 세션 격리 검증을 통과해야 한다.

**NFR-005 — Timing, Post-End, and Render Reliability**  
적격 세션 99%에서 5분 전 경고와 정확한 종료 알림이 예정 시각 ±5초 안에 전달되어야 한다. 세션 90% 이상은 종료 후 10초 안에 명시적 종료 후 상태에 진입하고 2분 안에 `Completed` 또는 `Phone Required`로 해결되어야 하며, 렌더 재시도나 실패가 유효 원본을 삭제·무효화해서는 안 된다.

**NFR-006 — Safe Local Packaging, Rollout, and Version Pinning**  
명시적으로 선택한 지점 집합에 단계적 배포가 가능해야 하며, 한 번의 승인된 롤백 작업으로 마지막 승인 앱 빌드와 프리셋 스택으로 복귀할 수 있어야 한다. 활성 세션 강제 업데이트는 0건이어야 하고, 완전한 서명 설치 패키지는 개발 도구가 없는 오프라인 Windows 환경에서 설치·실행·자가 점검·승인 픽스처 렌더·업그레이드·제거가 가능해야 한다.

**총 비기능 요구사항: 6개**

### 추가 요구사항 및 제약사항

#### 제품 및 사용자 경계

- 제품은 승인된 지점 하드웨어에서 실행되는 로컬 우선 Windows 데스크톱 부스 앱이다.
- 고객의 유일한 창작 제어는 승인·게시된 프리셋 선택이며, 직접 편집기나 darktable/XMP/모듈/라이브러리 용어는 고객에게 노출하지 않는다.
- 고객 상호작용 화면, 촬영 전 준비되는 읽기 전용 뷰어, 운영자 복구 화면, 권한 있는 프리셋 게시 워크플로의 책임과 권한을 분리한다.
- 예약 조회, 중앙 정책 동기화, 인쇄·전달 통합, 마케팅 자동화 및 확장된 지점 구성 관리는 MVP 이후 범위다.

#### 상태 및 진실 경계

- 핵심 상태는 `Preparing`, `Ready`, `Capturing`, `Preview Waiting`, `Review`, `Warning`, `Export Waiting`, `Completed`, `Phone Required`로 정의된다.
- 촬영 성공은 현재 세션에 새 원본이 안전하게 저장된 상태이며, 프리뷰 준비와 최종 완료는 서로 다른 후속 진실이다.
- 뷰어 성공은 동일 세션·요청·촬영·프리셋·게시 버전에 해당하는 물리적 디스플레이 맞춤 프레임이 실제 모니터에 제시된 경우에만 인정한다.
- 파일 준비, 렌더러 준비, 이벤트 수신, 디코드, 이미지 로드 콜백, 무필터 카메라 이미지 및 리뷰 썸네일은 뷰어 성공 근거가 아니다.
- 프록시에서 RAW 정제 결과로의 전환은 전체 디코드 이후에만 허용되며 빈 화면, 이전 촬영, 크롭·스케일 점프 또는 품질 단계 하락이 없어야 한다.

#### 명시적 정책 기준

- `Current-Session Deletion Policy`: 활성 세션에 속한 촬영과 연관 자산만 삭제할 수 있다. 선택 원본, 연관 프리뷰·최종 파생물, 해당 매니페스트 참조만 제거하며, 호스트 소유 변경 작업 중이거나 종료 후 완료 확정 뒤에는 삭제를 차단한다.
- `Session Timing Policy`: 승인된 입력으로 세션 시작 때 조정 종료 시각을 확정하고 항상 표시한다. T-5분에 경고하고 T=0에 종료하며, 승인·기록된 운영자 연장이 없으면 이후 새 촬영을 차단한다.
- `Operator Recovery Policy`: 차단 상태를 촬영, 프리뷰·렌더, 종료 후 복구 범주로 정규화한다. 허용 작업은 재시도, 승인된 경계 재시작, 승인된 시간 연장 또는 `Phone Required` 라우팅으로 제한한다.
- 종료 후 분류는 `Export Waiting`, `Completed / Local Deliverable Ready`, `Completed / Handoff Ready`, `Phone Required`로 한정한다.

#### 프리셋 게시 및 세션 안전

- 고객 카탈로그에는 안정된 ID·게시 버전·승인 렌더 호환성을 가진 1~6개의 불변 승인 프리셋만 표시한다.
- 프리셋 수명주기는 `draft`, `validated`, `approved`, `published`로 명시된다.
- 게시와 롤백은 미래 세션에만 적용하고 활성 세션 데이터나 프리셋 바인딩을 변경하지 않는다.
- 게시 아티팩트는 디스플레이 프록시 적격성, 지원 연산 집합, 버전된 프록시 레시피, 참조 렌더러 버전 및 승인된 시각 비교 결과를 포함한다.

#### 운영·배포 제약

- 촬영 진실과 렌더 진실은 호스트가 정규화한 세션 범위 상태에서 관리하며, mutable 제작·라이브러리 상태를 런타임 진실로 사용하지 않는다.
- 지점 배포와 롤백은 지점 집합, 대상 빌드, 승인 프리셋 스택, 승인 시각, 운영자 신원을 감사 기록으로 남긴다.
- 서명된 앱, 카메라 헬퍼, 승인 EDSDK 런타임, 디스플레이 렌더러 또는 셰이더 번들, 색상 프로필, 프록시 레시피, 고정 RAW 렌더러 의존성을 하나의 검증 가능한 인벤토리로 제공한다.
- 현재 세션의 원본과 승인된 작업은 재시도와 복구 과정에서도 보존한다.

#### 주요 사업 및 검증 기준

- 파일럿 60일 내 월간 지원 건수 250건 이하, 무인 첫 촬영 성공률 85% 이상, 20초 안 프리셋 선택 완료율 95% 이상을 목표로 한다.
- 승인 프리셋 재현율, 종료 시각 표시 정확도, 경고·종료 알림 신뢰도는 각각 99% 이상을 목표로 한다.
- 고객 관찰 검증은 무질문 시작·선택 80% 이상, 상태 이해 90% 이상, 시간 안내 이해 90% 이상을 요구한다.
- 운영자 예외 훈련의 90% 이상은 승인된 복구 동작만으로 처리되어야 하며, `Phone Required` 진입부터 첫 운영자 조치까지 평균 3분 이하여야 한다.

#### 미해결 가정 및 릴리스 의존성

- 이름과 전화번호 뒷자리만으로 충분한 처리량과 식별성을 확보할 수 있는지 UX 검증이 필요하다.
- 1~6개 프리셋이 선택 단순성과 고객 매력의 균형을 이루는지 파일럿 검증이 필요하다.
- 프리셋의 지점 간 시각 재현성, 승인 하드웨어 성능, 사전 오픈 뷰어 안정성, EOS 700D의 빠른 소스 경로, 상주 렌더러 성능·시각 동등성은 별도의 아키텍처·QA 증거가 필요하다.
- 운영자가 촬영과 렌더 실패를 제한된 진단만으로 구분할 수 있는지, 최종 렌더·핸드오프가 독립적으로 완료되어도 고객이 혼동하지 않는지 검증이 필요하다.
- 최종 MVP Go/No-Go는 설치, 성능·복구, 배포·롤백 증거가 독립적으로 완료되고 Epic 7 Story 7.10 및 HV-18D에 기록된 뒤에만 가능하다.

### PRD 완전성 평가

PRD에는 기능 요구사항 10개와 비기능 요구사항 6개가 명시적 번호, 행위자, 제품 상태, 정량 기준 및 수용 기준과 함께 정의되어 있다. 고객·운영자·권한 사용자 경계, 세션·프리셋·배포 정책, 종료 후 상태 분류와 릴리스 게이트도 구체적이다. 문서 자체의 요구사항 추출 기준에서는 중대한 구조적 누락을 발견하지 못했다.

다만 PRD가 직접 미해결로 표시한 하드웨어 성능, 프리셋 시각 동등성, EOS 700D 빠른 소스 경로, 뷰어 실제 표시 증거 및 운영 복구 가정은 구현 완료가 아니라 후속 검증 게이트다. 다음 단계에서 이 요구사항들이 에픽과 스토리에 실제로 추적되는지 확인한다.

## UX 정렬 평가

### UX 문서 상태

- 최신 UX 문서 `ux-design-specification.md`를 확인하고 전체 검토했다.
- 문서 상태는 `approved-readiness-12-issue-remediation`, 최종 수정일은 2026-08-11이다.
- UX 문서는 PRD, 아키텍처 및 저지연 관람 화면 연구를 입력으로 명시하고 있다.

### UX와 PRD 정렬

- 이름과 전화번호 뒷자리만 사용하는 시작 흐름, 1~6개 승인 프리셋, 고객 직접 편집 비노출 경계가 일치한다.
- 촬영 저장, `Preview Waiting`, 프리뷰 준비, 최종 완료를 서로 다른 진실로 취급하는 상태 모델이 일치한다.
- 현재 세션 검토·삭제, 이후 촬영에만 적용되는 프리셋 변경, 세션 간 자산 노출 0건 요구가 일치한다.
- 조정 종료 시각, 5분 전 경고, 정확한 종료, `Export Waiting`·`Completed`·`Phone Required` 흐름이 일치한다.
- 촬영 전 사전 준비 뷰어, 물리적 디스플레이 맞춤 첫 프레임, actual-present 성공 기준, 프록시에서 RAW 정제 결과로의 무중단 전환이 일치한다.
- 고객 문구 밀도, 내부 진단어 비노출, 운영자와 프리셋 관리자 권한 분리 요구가 일치한다.
- WCAG 2.2 AA와 실부스 사용성은 PRD 범위를 확장하는 새 FR/NFR이 아니라 UX 릴리스 증거 `UX-EV-01`, `UX-EV-02`로 명시적으로 분리되어 있다.

### UX와 아키텍처 정렬

- 아키텍처는 고객 조작 화면, 사전 오픈 읽기 전용 뷰어, 운영자 콘솔, 권한 있는 프리셋 제작 화면을 분리된 capability-gated surface로 지원한다.
- Rust 호스트의 단일 정규화 상태와 React의 고객·운영자별 투영 구조가 UX의 상태 진실성 및 고객 안전 문구 요구를 지원한다.
- `viewer-surface`, `display-generation`, Rust `viewer`·`display` 경계와 하드웨어 테스트 위치가 UX-DR18~20을 직접 지원한다.
- 실제 photo rectangle과 DPR 기반 크기, 불변 generation, 완전 디코드 이후 pointer 전환, opaque double-buffer, actual monitor-present 계측이 UX 관람 계약과 일치한다.
- 세션 폴더 진실, 상관 ID, 캡처별 프리셋 버전 고정 및 미래 세션 전용 게시·롤백 구조가 현재 세션 격리와 프리셋 일관성을 지원한다.
- 호스트 소유 시간 정책, 완료 상태, 오류 envelope 및 운영자 복구 경계가 UX의 대기·경고·도움 요청 흐름을 지원한다.
- 관리자 비밀번호, privileged session, capability enforcement를 Story 1.10이 소유하도록 해 고객 흐름에서 내부 진입점을 숨기는 UX 요구를 지원한다.
- `shared-ui`, booth/customer flow, 접근성 E2E 테스트 및 `UX-EV-01`·`UX-EV-02` 증거 소유권이 접근성·실부스 사용성 요구를 지원한다.
- Brutal Core, Tailwind/Headless UI 우선 검토, 80px 터치 기준은 UX에서 설계 가이드 또는 검증 전 기준선으로 구분되어 있어 아키텍처의 기술 선택과 충돌하지 않는다.
